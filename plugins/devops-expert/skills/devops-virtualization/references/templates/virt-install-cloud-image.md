# Template: Cloud Image + NoCloud with `virt-install`

## Usage

Run on the KVM host after the read-only inventory ([../libvirt-domains.md](../libvirt-domains.md)) and the user's go. Options verified in the virt-install man source (`--import`, `--disk size/backing_store/backing_format/format/bus`, `--network bridge=`, `--cloud-init user-data=,meta-data=,network-config=`, `--print-xml`, `--noautoconsole`), read 2026-11-10. Replace every `<...>`. The three data files are the sibling templates: [nocloud-user-data.yaml](nocloud-user-data.yaml), [nocloud-meta-data.yaml](nocloud-meta-data.yaml), [nocloud-network-config.yaml](nocloud-network-config.yaml).

## Variables

```bash
URI=qemu:///system
POOL=/srv/vm/images                      # a libvirt dir pool, see libvirt-storage-networks.md
BASE=$POOL/base/<distro>-cloudimg.qcow2  # read-only base image, never booted directly
VM=web01
```

## 1. Fetch and verify the base image

```bash
mkdir -p "$POOL/base"
curl -fLo "$BASE" <official-cloud-image-url>      # URL from the distribution's cloud-image page
sha256sum "$BASE"                                  # compare with the distribution's published checksum file
qemu-img info "$BASE"                              # format qcow2, virtual size
chmod a-w "$BASE"                                  # protect the backing file
```

## 2. Validate the seed data

```bash
cloud-init schema -c nocloud-user-data.yaml --annotate    # on any machine with cloud-init installed
cloud-init schema -t network-config -c nocloud-network-config.yaml   # top-level "network:" handling not verified
python3 -c 'import yaml,sys; [yaml.safe_load(open(f)) for f in sys.argv[1:]]' \
  nocloud-meta-data.yaml nocloud-network-config.yaml
```

## 3. Preview, then create

```bash
virt-install --connect "$URI" --name "$VM" --memory 2048 --vcpus 2 \
  --import \
  --disk path="$POOL/$VM.qcow2",size=20,format=qcow2,backing_store="$BASE",backing_format=qcow2,bus=virtio \
  --network bridge=br0,model=virtio \
  --osinfo <osinfo-short-id> \
  --cloud-init user-data=nocloud-user-data.yaml,meta-data=nocloud-meta-data.yaml,network-config=nocloud-network-config.yaml \
  --noautoconsole --print-xml > /root/$VM.xml          # review the XML: defines nothing
# Same command without --print-xml, after review and go, creates the overlay and starts the guest.
```

`--cloud-init` generates a NoCloud ISO attached as a CD-ROM "only for the first boot" (man page). `size=20` is the overlay's virtual size in GiB and must be at least the base image size.

## Verification

```bash
virsh -c "$URI" domstate "$VM"                            # running
virsh -c "$URI" domifaddr "$VM" --source agent            # needs qemu-guest-agent (installed by the user-data)
ssh <admin-user>@192.168.150.10 'cloud-init status --wait --long'   # status: done, no errors
```

## Rollback

Guest wrong: `virsh -c "$URI" shutdown "$VM"`, then after the user's go `virsh -c "$URI" undefine "$VM"` (for a UEFI guest it fails unless `--nvram` or `--keep-nvram` is given) and delete only `$POOL/$VM.qcow2` (the overlay). The base image stays. `destroy` is a hard power-off, not a deletion.

## Not verified

- The `--osinfo` short id for your image; the exact cloud image URL and checksum file name per distribution.
- Whether `size=` smaller than the base is rejected or ignored by your virt-install version.
- First-boot disk growth depends on the image's cloud-init `growpart` default (documented module, not run here).
