# Argo CD Applications

**Load when:** an `Application`, `AppProject` or `argocd` command is involved. Version 3.6.1 (released 2026-11-04). All Application and AppProject objects live in the Argo CD namespace (default `argocd`). Templates: [application.yaml](templates/argocd/application.yaml), [appproject.yaml](templates/argocd/appproject.yaml).

## Core objects

| Object | Key fields |
|--------|-----------|
| `Application` (`argoproj.io/v1alpha1`) | `spec.project`, `spec.source` (`repoURL`, `targetRevision`, `path` or `chart`, `helm`/`kustomize`/`directory`), `spec.destination` (`server` **or** `name`, `namespace`), `spec.syncPolicy`, `spec.ignoreDifferences` |
| `AppProject` | `sourceRepos`, `destinations`, `clusterResourceWhitelist`/`Blacklist`, `namespaceResourceWhitelist`/`Blacklist`, `roles`, `syncWindows`, `sourceNamespaces` |

Git-hosted chart: use `path`; Helm repository chart: use `chart` (and `targetRevision` = chart version). A project whose `destinations` include the Argo CD namespace grants admin-level access: never give it to tenants.

## Decision rules: sync policy

| Setting | Meaning (sync policy docs) | Default stance |
|---------|----------------------------|----------------|
| `automated: {}` | Sync when the app is OutOfSync; one attempt per commit SHA plus parameters; no retry of a failed attempt on the same SHA | Staging yes, production only with the owner's go |
| `automated.prune: true` | Delete live resources no longer in Git | Off. Without it, a manual sync can still prune |
| `automated.allowEmpty` | Allow an app to end up with zero resources (guard against empty-render accidents) | Never true |
| `automated.selfHeal: true` | Re-sync when live state drifts (default delay 5 s) | On where manual `kubectl edit` must not survive; off while someone is debugging |
| `retry` (`limit`, `backoff.duration/factor/maxDuration`) | Exponential retry of failed syncs; `limit: -1` = unlimited | `limit: 5`, `maxDuration: 3m` |
| `syncOptions: CreateNamespace=true` | Create the destination namespace | Fine for non-shared namespaces |
| `Prune=false` / `Prune=confirm` (resource annotation `argocd.argoproj.io/sync-options` or app-level `syncOptions`) | Never prune / require confirmation before pruning | `Prune=confirm` on Namespaces, PVCs, CRDs |
| `Delete=false` / `Delete=confirm` | Keep / confirm before deleting the resource when the **app** is deleted | `Delete=false` on PVCs |
| `PruneLast=true` | Prune as a final implicit wave after other waves are healthy | On when ordering matters |
| `ServerSideApply=true` | Server-side apply | Not read in detail today; verify before use |
| `Replace=true` | `kubectl replace` instead of apply | Only for objects too big for `last-applied`; destructive-ish |
| `ApplyOutOfSyncOnly=true` | Apply only drifted resources | For apps with thousands of objects |

Auto-sync facts: reconciliation interval is `timeout.reconciliation` in `argocd-cm` (default 120 s plus up to 60 s jitter); **rollback cannot be performed on an app with automated sync enabled**; for apps generated by an ApplicationSet, changing `syncPolicy.automated` on the child has no effect (change the ApplicationSet).

## Ordering: phases, waves, hooks

Hooks (`argocd.argoproj.io/hook`): `PreSync`, `Sync`, `Skip`, `PostSync`, `SyncFail`, `PreDelete`, `PostDelete`. A failed PreSync stops the sync. Waves: `argocd.argoproj.io/sync-wave: "<int>"`, default 0, negative allowed, lowest first, 2 s delay between waves (`ARGOCD_SYNC_WAVE_DELAY`). Order of precedence: phase, wave, kind (Namespaces first), name. Pruning runs in reverse wave order. Cleanup: `argocd.argoproj.io/hook-delete-policy` (`HookSucceeded`, `HookFailed`, `BeforeHookCreation`, which is the default). Do not use `ttlSecondsAfterFinished` on hook Jobs. Hooks do not run on a selective sync.

## Commands

```bash
argocd app diff web --refresh                      # exit 0 none, 1 diff, 2 error; Secrets excluded from the diff
argocd app sync web --dry-run                      # preview apply
argocd app sync web --preview-changes              # diff then wait for confirmation
argocd app sync web --prune --dry-run              # preview what a prune would delete
argocd app sync web --revision <git-sha>           # after the user's go
argocd app history web ; argocd app rollback web <id>   # history ids; rollback needs auto-sync off
```

## Destructive: propose, then the user's go

| Command | Exact effect | Before proposing |
|---------|--------------|------------------|
| `argocd app sync <app> --prune` or `automated.prune: true` | Deletes live resources absent from Git, in reverse wave order | `argocd app sync --prune --dry-run` list; PVC, Namespace, CRD in it? use `Prune=confirm` |
| `argocd app sync <app> --force` / `--replace` | Force apply / `kubectl replace`: pods restart, fields reset | Prefer a normal sync |
| `argocd app delete <app>` (= `--cascade`) | Deletes the Application **and all its managed resources** (foreground by default) | Resource list (`argocd app resources`), `Delete=false` on data objects, backups; PreDelete hooks run |
| `argocd app delete <app> --cascade=false` | Deletes only the Application; resources stay running, unmanaged | Say which resources are orphaned |
| `argocd app rollback <app> <id>` | Syncs back to a previous history entry (`--prune` also deletes) | Auto-sync must be disabled; Git still holds the new version, so a later sync undoes it |
| `kubectl delete app <app>` | Cascade only if the app has the `resources-finalizer.argocd.argoproj.io` finalizer | Check `metadata.finalizers` first |

```
ACTION   argocd app delete web --cascade   (project shop, cluster prod-eu)
EFFECT   deletes Deployment web, Service web, ConfigMap web-config, PVC data-web (reclaimPolicy Delete: data lost) in ns shop
PROOF    argocd app resources web listing attached; backup id <id>; Delete=false not set on PVC
WAIT-FOR-GO  yes
```

## Pitfalls

| Trap | Consequence |
|------|-------------|
| `targetRevision: HEAD` in production | Every merge deploys; pin a tag or SHA and promote by editing it |
| Application without the finalizer | Deleting it leaves all resources running (orphaned) |
| App stays OutOfSync after sync | Mutating webhook, controller-written fields or `randAlphaNum`: use `ignoreDifferences` (`jsonPointers`, `jqPathExpressions`, `managedFieldsManagers`) deliberately |
| `ignoreDifferences` on `/spec/replicas` while an HPA exists | Required to stop the fight; omit it when no HPA |
| Two projects, same destination namespace | Overlapping ownership; one namespace, one owner |
| Helm hooks in a chart | Mapped to Argo CD hooks; delete-policy semantics follow Argo CD phases, not Helm events |

## Verification

`argocd app get web` shows `Synced` and `Healthy` at the intended revision; `kubectl rollout status`; the user-facing check. `Synced` does not prove the service works.
