# VPN

## Overview (vpnet.html)
SSL VPNs (OpenVPN), IPsec, and WireGuard/ZeroTier via plugins are the listed technologies.

## WireGuard
- Install plugin `os-wireguard` (System > Firmware > Plugins) per the site-to-site how-to; menu then at VPN > WireGuard (Instances, Peers, Peer generator). Whether it is now in core in 26.7 was not read.
- Instance: listen port (51820 or another unique port), MTU 1420 default (1412 for PPPoE; 80 bytes less than WAN MTU), tunnel address in CIDR as a unique subnet, never a /32 or /128. Leave the instance DNS server blank, or WireGuard overwrites OPNsense DNS config.
- Public key is generated by the cogwheel; save, reopen, copy public key. Peer generator exists for clients; with Unbound, set the client DNS to the tunnel address.
- In HA, set "Depend on (CARP)" on each instance (wireguard-s2s.html).
- You still need firewall rules on WAN (listen port) and on the WireGuard interface group. Step details beyond the first screens were not read.

## IPsec (vpnet.html)
- Configured as Connections (swanctl.conf format, strongSwan). Menu items: Connections, Pre-Shared Keys, Key Pairs, Mobile & Advanced Settings, Status Overview, Lease Status, SAD, SPD, Virtual Tunnel Interfaces (`if_ipsec`), Log File.
- Old Phase 1 = connection settings; Phase 2 = children (CHILD_SA).
- 26.7.8 notes: IKEv1 deprecation in strongSwan is more visible; plan to move away from IKEv1.

## OpenVPN
- 26.7 ships OpenVPN 2.7. The "instances" configuration model and its menu path were not read (the how-to URL tried returned 404).

## Lock-out rule
Deleting or editing the VPN instance you manage through = ACTION/EFFECT/PROOF/ROLLBACK/WAIT-FOR-GO with a non-VPN path kept ([safe-opnsense-changes.md](safe-opnsense-changes.md)). Binding the GUI/SSH to a VPN interface is unsupported (settingsmenu.html).
