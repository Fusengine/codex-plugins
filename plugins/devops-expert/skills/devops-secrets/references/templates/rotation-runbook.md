## Preconditions (read-only)
1. Current state captured: version/lease/metadata ID `<id>` (no value).
2. Backup or snapshot of the system of record taken and a restore known to work: `<snapshot ID>`.
3. Consumers healthy (`kubectl get pods`, `vault status`, pipeline green).
4. Rollback point defined: old credential still valid until step 6.

## Steps
1. **Create** the new credential: `<command, values read from a file or generated by the store>`.
2. **Store** it in the system of record: `<command>`; record new version `<id>`.
3. **Distribute**: `<sync / apply / pipeline>`; wait for `<ExternalSecret Ready | rollout status | file refresh>`.
4. **Reload consumers**: `<restart / signal>`; one canary first: `<name>`.
5. **Verify new**: test client authenticates with the new credential (values from files, not arguments); consumers show no auth errors for `<N>` minutes.
6. **Revoke old** (ACTION / EFFECT / PROOF / WAIT-FOR-GO if it is not trivially reversible): `<command>`; record time.
7. **Verify old fails**: test client with the old credential is refused.
8. **Record**: date, versions, operator, anomalies.

## Rollback
- Before step 6: re-point consumers to the previous version `<command>`; delete the new credential at the issuer.
- After step 6: issue a fresh credential (repeat steps 1-5); the old one cannot be restored.

## Emergency (suspected leak)
Skip the overlap: revoke first (step 6), then rotate and distribute; follow `leaked-secret-response.md`.
