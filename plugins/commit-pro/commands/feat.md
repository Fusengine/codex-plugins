# Quick Feature Commit

## Current State

Run `git status` and use the output.

## Changes

Run `git diff --stat` and use the output.

## Instructions

Before any write action, ask explicit user confirmation. This includes `git add`, `git commit`, tags, push, branch creation, reset, and revert.

Create a quick feature commit.

1. Stage all changes: `git add -A`
2. Analyze modified files to determine scope
3. Generate commit message:
   - If `$ARGUMENTS` provided: `feat(scope): $ARGUMENTS`
   - If empty: analyze diff and generate description
4. Format: `feat(scope): imperative description`
5. **NO AI SIGNATURE**: Never add Co-authored-by, Generated by, or any AI mention
6. Ask confirmation before committing
7. Execute and show result
8. Execute the `post-commit` skill (CHANGELOG + version bump only — no tag here; tagging is handled post-merge by the `commit` command's Steps 7–9 (merge, tag, release-workflow watch), not by this quick command — never call a release "published" from here)

**Note**: All commits trigger **PATCH** bump only (1.37.0 → 1.37.1). MINOR/MAJOR bumps are manual user decisions.
