# WIP Commit

## Current State

Run `git status` and use the output.

## Current Branch

Run `git branch --show-current` and use the output.

## Instructions

The owner's manual quick save: one commit on the working branch, invoked by the owner. Agents and the lead never invoke it — every agent-side commit goes through the `commit` agent (`plugins/ai-pilot/agents/commit.toml`, WIP mode). A WIP commit never leaves the machine: no push, no version bump, no CHANGELOG, no PR, no merge, no tag.

Before any write action, ask explicit user confirmation. This includes `git add`, `git commit`, and branch creation.

1. **Branch check** (same rule as the `commit` agent's WIP mode): on `main`, `master`, `develop` or `production`, never commit there: create a working branch `<type>/<scope>` (`git checkout -b`) and commit on it. On a feature branch, stay.
2. **Security check** on every file you are about to stage (`git status --porcelain`, `git diff`): block on `.env`, `.env.*`, `*.pem`, `*.key`, `*credentials*`, and on `password=`, `secret=`, `api_key=`, `token=` patterns. A blocked file is left out and named in the output.
3. **Stage explicitly**: `git add -- <paths>` for the files that passed the check. Never a blind `git add -A` / `git add .`.
4. Generate the commit message:
   - If `$ARGUMENTS` provided: `wip: $ARGUMENTS`
   - If empty: `wip: work in progress`
5. **NO AI SIGNATURE**: Never add Co-authored-by, Generated by, or any AI mention
6. Execute only after confirmation.
7. Show the result: branch, short hash, files committed, files left out by the security check.

**Why `wip:` here and `type(scope):` in the commit agent**: WIP commits stay in the branch history — the branch is merged at the end of the mandate by the commit agent's full flow with a real merge (`--merge`), never squash (it would orphan the release tag target). The commit agent's WIP mode therefore writes conventional `type(scope): description` messages that read well in that history. This command is the owner's own checkpoint, so its `wip:` prefix is his explicit choice.
