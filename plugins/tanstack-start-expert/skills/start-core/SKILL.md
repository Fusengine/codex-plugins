# TanStack Start Core

TanStack Start is a full-stack React framework built on **TanStack Router + Vite**
(Rsbuild also supported). It adds SSR, streaming, server functions (type-safe
RPCs), middleware, and universal deployment. This skill targets
`@tanstack/react-start` **v1.169.5**.

> **CRITICAL — Start is NOT Next.js.** No `getServerSideProps`, no `"use server"`
> directives, no `app/layout.tsx`. Routes live in `src/routes/`; server-only code
> uses `createServerFn`.
>
> **CRITICAL — code is isomorphic by default.** Loaders run on server AND client.
> See the `start-execution-model` skill before putting logic in a loader.
>
> **CRITICAL — types are fully inferred.** Never cast or annotate inferred values.

## Agent Workflow (MANDATORY)

Before implementing, verify current APIs against Context7
(`/websites/tanstack_start_framework_react`) + Exa, then explore the target
codebase. After changes, run `sniper`.

## The Two Required Files

Every Start app needs exactly two hand-written wiring files plus one generated:

1. **`src/router.tsx`** — a `getRouter()` factory returning `createRouter({ routeTree })`.
2. **`src/routes/__root.tsx`** — the document shell (`<html>`, `HeadContent`,
   `Outlet`, `Scripts`).
3. **`src/routeTree.gen.ts`** — GENERATED by the plugin. Never edit.

## Minimal Setup (glance)

```ts
// vite.config.ts — Start plugin MUST come before React's
import { defineConfig } from 'vite'
import { tanstackStart } from '@tanstack/react-start/plugin/vite'
import viteReact from '@vitejs/plugin-react'

export default defineConfig({
  server: { port: 3000 },
  plugins: [tanstackStart(), viteReact()],
})
```

```tsx
// src/router.tsx
import { createRouter } from '@tanstack/react-router'
import { routeTree } from './routeTree.gen'

export function getRouter() {
  return createRouter({ routeTree, scrollRestoration: true })
}
```

## Scaffolding Shortcut

Instead of building by hand, the CLI scaffolds a working project:

```bash
npx @tanstack/cli@latest create
# or clone an official example:
npx gitpick TanStack/router/tree/main/examples/react/start-basic start-basic
```

### Headless empty-folder default (TanStack Start + shadcn/ui + Lucide)

Used when the folder is empty, no stack is named and nobody can answer (owning rule:
`codex-rules/rules/05-frontend-rules.md` rule 3). Never hand-write the scaffold.
Verified 2026-11-23 (`@tanstack/cli` 0.72.16, `shadcn` 4.23.0, node 26, empty dir, `CI=1`,
stdin closed):

```bash
# 1. Scaffold in the current dir (`.`; no --target-dir). A failing
#    `@tanstack/intent install` step is non-blocking.
npx -y @tanstack/cli@latest create . -y --package-manager npm --no-git </dev/null
# 2. tsconfig.json: remove the `"#/*": ["./src/*"]` path alias, keep `"@/*": ["./src/*"]`.
#    Otherwise shadcn init hits a "Would you like to use TypeScript?" prompt and exits 0
#    WITHOUT writing components.json. tsconfig may be JSONC: edit it with the file-edit
#    tool (`apply_patch` in Codex), never jq. Check: must print 0. grep exits 1 when the
#    count is 0 — expected, not a failure (do not run it under `set -e`):
grep -c '"#/\*"' tsconfig.json
# 3. shadcn/ui init (Start template, Radix base, preset nova):
npx -y shadcn@latest init -t start -b radix -p nova -y </dev/null
# 4. Components:
npx -y shadcn@latest add <components> -y
```

- Presets: `nova`, `vega`, `maia`, `lyra`, `mira`, `luma`, `sera`, `rhea` (`-p radix-nova`
  is rejected). Never `-d` (forces the `next` template). Omitting `-b` → blocking
  "Select a component library" prompt.
- Do not use the TanStack `shadcn` add-on; follow ui.shadcn.com/docs/installation/tanstack.
- **Proof:** `components.json` exists with `"iconLibrary": "lucide"`, `lucide-react` is in
  `package.json`, `npm run build` exits 0. Exit 0 of `init` alone is NOT success.
- Sources: tanstack.com/cli/latest/docs/cli-reference, ui.shadcn.com/docs/cli.

## Forbidden

- React Vite plugin placed before `tanstackStart()` (breaks generation).
- Editing `src/routeTree.gen.ts` (generated).
- Omitting `<Scripts />` in `__root.tsx` (no hydration).
- Enabling `verbatimModuleSyntax` (leaks server code into client bundle).
- Next.js/Remix patterns (`getServerSideProps`, `"use server"`).
